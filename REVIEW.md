# REVIEW.md

List every defect found in the assigment `app/main.py` :

| # | Where | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `app` startup | No indexes were created when the app starts. | Duplicate records can be saved at the same time, and queries are slow on big data. | Added a `lifespan` function to create unique and normal indexes when the server starts. |
| 2 | `compute_late_minutes` | 1) It did not convert time to IST. 2) It divided by 60 before checking the 10-minute grace time, so `09:40:01` became `10` minutes and returned `0` instead of `10`. | If shift is `09:30` and punch-in is `09:40:01`, it gives `0` late minutes instead of `10`. | Converted both times to IST and checked if total seconds are more than `600` (10 minutes) before calculating minutes. |
| 3 | `compute_work_hours` | Python's `round()` function uses banker's rounding instead of normal half-up rounding, and it did not remove milliseconds first. | Some work hour values round down instead of rounding up to 2 decimal places. | Removed microseconds first and used Python's `Decimal` with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` | 1) Mixing naive datetime and IST datetime gives a Python error. 2) It did not handle night shifts that end the next day. 3) It did not check the 30-minute minimum rule. | Working 15 minutes extra gave `15` overtime instead of `0`, and night shifts gave wrong overtime. | Converted `punch_out` to IST, added 1 day to `shift_end` for night shifts (`shift_end <= shift_start`), and returned `0` if overtime is less than 30 minutes. |
| 5 | `EmployeeIn` & `PunchInIn` models | Input validation rules were missing (like `emp_code` format, valid email, `shift_start != shift_end`, valid date, and allowed status values). | Wrong data like `status="ABSENT"` in punch-in or invalid dates were getting saved without throwing a `422` error. | Added Pydantic `Field` rules, regex patterns, Enums, and a validator to check shift times and dates. |
| 6 | `health` | It always returned `{"status": "ok"}` without checking if MongoDB is actually working. | Even if MongoDB is stopped, `/health` still returns `200`. | Added `client.admin.command("ping")` inside `try-except` to check the database connection. |
| 7 | `create_employee` | 1) Used `find_one` before `insert_one`, which fails if two requests come together. 2) Used `datetime.now()` without UTC. 3) Returned `created_at` as a date string instead of epoch milliseconds. | Two fast requests can crash with a `500` error, and `created_at` is not a number in the response. | Removed `find_one`, caught `DuplicateKeyError` to return `409`, used UTC time, and converted `created_at` to milliseconds. |
| 8 | `list_employees` | 1) `skip = page * page_size` skipped the first page when `page=1`. 2) `count_documents({})` counted all employees instead of filtered department employees. 3) Sorting by `emp_code` was missing. 4) `created_at` was not in milliseconds. | Page 1 showed page 2 data, department total was wrong, and list was not sorted. | Changed skip to `(page - 1) * page_size`, passed query `q` into `count_documents(q)`, added `.sort("emp_code", 1)`, and converted `created_at` to milliseconds. |
| 9 | `punch_in` | 1) Did not return `404` if employee does not exist. 2) Did not handle night shift dates before shift end time. 3) Used `find_one` before `insert_one`. 4) Returned extra `id` field and did not convert `punch_in` to milliseconds. | Passing an unknown employee crashes with `500`, night shift punches get the wrong date, and response format does not match the contract. | Added `404` check for missing employee, fixed night shift date logic in IST, caught `DuplicateKeyError` for `409`, removed `id`, and converted dates to milliseconds. |
| 10 | `list_attendance` | 1) Loaded all database records into a Python list, which is very slow for 100,000 records. 2) Did not check `date_from <= date_to`. 3) Returned `id` and did not convert date fields to milliseconds. | App becomes very slow on large data, and `date_from > date_to` does not give a `422` error. | Used MongoDB `.sort()`, `.skip()`, and `.limit()` directly on the query, added date validation, and formatted all dates to milliseconds. |

### Things I checked and decided were NOT defects

1. **`load_dotenv()` at the top of the file:** By default, `load_dotenv()` does not overwrite system environment variables, which follows the rule that real environment variables must win.
2. **Saving `date`, `joined_on`, `shift_start`, and `shift_end` as strings:** `DATA_MODEL.md` says calendar dates and shift times should be kept as strings (`YYYY-MM-DD` and `HH:MM`) so timezone issues do not change them, while actual timestamps (`punch_in`, `punch_out`, `created_at`) are stored as MongoDB dates.
